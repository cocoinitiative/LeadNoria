## 2. REPAIRED DEFECT DETAILS

### Defect A: Multi-Locale Month Token Boundary in Contextual ID Extractor
- **File:** [src/extension/metaAdapter.ts](file:///e:/project%20anti/leadnoria/src/extension/metaAdapter.ts#L295-L310)
- **Root Cause:** In `extractAdIdentifier`, Pattern 1 (explicit `Library ID: ...`) was upgraded to support Spanish, French, German, Italian, and Portuguese month abbreviations (`Jan|...|Dic|Janv|Févr|Mars|...|Ott`), but Pattern 2 (contextual `\bID\s*:\s*[0-9]+`) still contained only English months (`Jan|...|Dec`). If a non-English ad card used contextual ID formatting with adjacent day-of-month digits, the fused digits were not cleanly trimmed.
- **Fix:** Extracted `multiLocaleMonthRegex` into a shared regex and applied it to both explicit and contextual branches.
- **Verification:** Unit tests in `test-v175-qualification-and-id-hardening.mjs` confirmed clean boundary extraction for all locales.

### Defect B: Normalized Intent Fallback Scope in Lead Creation
- **File:** [src/extension/metaAdapter.ts](file:///e:/project%20anti/leadnoria/src/extension/metaAdapter.ts#L950)
- **Root Cause:** In `aggregateCandidatesToLeads`, `actualIntent` was normalized to support callers passing intent without an explicit `existingLeads` empty array. However, on line 947, `matchedKeywords` fallback still referenced `intent?.primaryKeywords` instead of `actualIntent?.primaryKeywords`.
- **Fix:** Updated the fallback expression to `actualIntent?.primaryKeywords?.slice(0, 1) || []`.
- **Verification:** Regression test 4.1 in `test-v175-qualification-and-id-hardening.mjs` verified clean aggregation.
